# Acme Cloud Support Chatbot — RAG Demo

A working retrieval-augmented generation pipeline over a fictional SaaS help center ("Acme Cloud"), built as a portfolio case study. Ask a support question, get an answer synthesized from the docs with cited sources. Includes a hand-labeled eval set with measured retrieval metrics — real numbers, generated by `evals/run_evals.py`, not estimates.

## The problem

Support teams drown in repetitive tickets that are already answered in the docs. Keyword search over help centers misses paraphrased questions ("how much is growth?" vs. "Growth — $29/month per seat"). A RAG chatbot fixes this: semantic retrieval finds the right doc section even when the wording differs, and cited answers keep every claim traceable to a source instead of hallucinated.

## What was built

- **Corpus** (`corpus/`): 8 realistic help-center docs written for this demo — getting started, pricing, API auth, webhooks, troubleshooting, security & compliance, billing, integrations.
- **Pipeline** (`rag/`): ingest → chunk → embed → retrieve → answer.
  - `ingest.py` — splits markdown on `##` headings into ~300-word chunks with 40-word overlap (54 chunks total; deterministic ids).
  - `embed.py` — embeds with `all-MiniLM-L6-v2` (sentence-transformers). In restricted networks the model can be pre-fetched into `models/` and loaded via `ST_MODEL_DIR`; a TF-IDF fallback keeps the pipeline runnable anywhere. The active backend is recorded in the saved index.
  - `retrieve.py` — cosine-similarity top-k search.
  - `answer.py` — **extractive** answering: synthesizes the answer from retrieved sentences, always with citations. The generation layer is pluggable — swap `synthesize()` for an LLM API call to get abstractive answers.
  - `demo.py` — CLI: `python rag/demo.py "your question"`.
- **Evals** (`evals/`): 10 hand-written questions, each labeled with the doc(s) containing the answer (ground truth, since the corpus was authored for this demo). `run_evals.py` computes recall@3 and MRR and writes `evals/results.json`.

## Architecture

```
corpus/*.md → ingest (heading chunks) → embed (MiniLM-L6-v2, 384-d)
    → index.pkl → retrieve (cosine top-3) → answer (extractive + citations)
                                                        ↓
                                              evals/ (recall@3, MRR)
```

## Eval results

Measured by `evals/run_evals.py` on the 10-question hand-labeled set (backend: `all-MiniLM-L6-v2`):

| Metric | Score |
|---|---|
| recall@3 | **1.00** |
| MRR | **0.90** |

8 of 10 questions retrieve the correct doc at rank 1. The 2 misses both rank the right doc at #2: pricing questions like "How much does the Growth plan cost?" where the troubleshooting doc's "Out of build minutes" section (which quotes plan minute limits) is a genuinely close semantic neighbor. That's an honest signal — on a small corpus, adjacent docs compete.

## Tech stack

Python 3.12 · sentence-transformers (`all-MiniLM-L6-v2`) · scikit-learn (TF-IDF fallback) · NumPy · stdlib only otherwise. No API keys, no network calls at query time.

## How to run

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt

# build the index (downloads the embedding model on first run;
# in restricted networks, pre-fetch weights into models/ and set ST_MODEL_DIR)
ST_MODEL_DIR=$PWD/models/all-MiniLM-L6-v2 .venv/bin/python rag/embed.py

# ask a question
.venv/bin/python rag/demo.py "How do I verify a webhook signature?"

# run evals
.venv/bin/python evals/run_evals.py   # → evals/results.json
```

## Production hardening — what's demo-grade vs. what I'd change

**Demo-grade (fine here, not in production):**
- Extractive answers — safe against hallucination, but stitched sentences read mechanically. Production: abstractive generation via an LLM API with a "answer only from context, cite chunk ids" system prompt.
- Single-vector dense retrieval. Production: hybrid search (dense + BM25) plus a cross-encoder reranker on the top-20 — this would fix the rank-2 pricing misses above.
- 10-question eval set. Production: 100+ questions including adversarial/paraphrased ones, plus faithfulness and citation-precision metrics, run in CI.

**Already production-shaped:**
- Deterministic chunk ids, citations on every answer, backend recorded in the index, evals as a runnable script with committed outputs.
